# HANDOFF — «Домик на дереве» (рабочее название репозитория: zombie)

Документ для нового разработчика. Прочитай целиком — вопросов к владельцу (Павел) быть не должно.
Владелец не программист, общается по-русски, с телефона. Ему важны **атмосфера и качество картинки**, честность («не говори "работает", пока не проверил») и короткие простые ответы.

---

## 1. Смысл игры

- **Что это.** Уютная мобильная 3D-игра про выживание. Человечек живёт в домике на огромном дубе посреди туманного леса. Днём он живёт обычной жизнью, ночью из тумана приходят зомби и лезут к домику физическими путями, а игрок помогает их отбить.
- **Для кого.** Казуальные игроки iPhone, которые любят уютные «cozy»-игры с атмосферой (жанр: cozy survival). Не хардкор и не «Fallout»: никакой мрачной стилистики бункеров.
- **Что делает игрок.** Сейчас он смотрит на живой домик: крутит камеру пальцем, приближает щипком, наблюдает смену дня и ночи. Боевой режим (ночью тап по зомби — герой стреляет из лука) написан, но **сейчас выключен по просьбе владельца** (см. раздел 6). Дальше по плану: укрепление домика досками (каждая доска — физический объект), прогресс, другие убежища (поезд, домик на скале) и онлайн-слой.
- **Человечек.** Молодой выживальщик: кожаный жилет, горчичный свитер, зелёные штаны, колчан (референс `assets/refs/hero-ref.png`). Он **постоянно чем-то занят**, ходит по домику и по лестницам сам:
  - днём готовит у печки, моет посуду, пьёт чай, читает за столом в спальне (садится на стул), мастерит за верстаком, смотрит вдаль с площадки;
  - вечером читает при лампе, ночью спит на нижней полке двухъярусной кровати;
  - утром встаёт.
  
  Лампы днём выключены, ночью горят.
- **Зомби** (референс `assets/refs/zombie-ref.png`, вид на концепте `concept/4-domik-noch-miniatura.png`) — худые серо-зелёные, светящиеся жёлтые глаза. Они **не телепортируются**: идут по земле, лезут по лестнице или сваям, ломают доски заборчиков. При попадании стрелы падают по физике тела (ragdoll).

## 2. Как должно выглядеть

- **Эталон:** `concept/1-domik-razrez-3d.png` — разрез домика на дереве, синие сумерки, туман, тёплый свет в комнатах. Владелец требует **один в один**: дерево, листва, доски, окна, крыши, земля, туман, цвет, свет, тени.
- **Главное правило: «3D-мир по фото, а не ожившая фотография».**
  - Это настоящий 3D-мир с физикой: камеру можно крутить, у каждого предмета есть объём и границы, а герой и зомби ничего не проходят насквозь.
  - Плоский 2D-коллаж с анимацией владелец уже отверг (версия `th2`).
  - Стартовый ракурс должен максимально совпадать с эталоном. Виды с других сторон дорисовываются в том же стиле.
- **Стиль.** Стилизованная рисованная 3D-графика (как в cozy-играх и мультфильмах).
  - Тёплое дерево: оранжевые широкие доски пола, светлые доски стен.
  - Сине-серая черепица.
  - Сине-бирюзовый туман и небо, сочная зелёная листва дуба с жёлтыми листьями.
  - Никаких улыбающихся лиц и «мордочек» на предметах (владелец просил отдельно). UI минимальный: маленькие чипы и иконки.
- **Шаблон для предметов (как рисуем ассеты):**
  1. Картинку предмета генерируем из эталона: модель `fal-ai/nano-banana-pro/edit`, в `image_urls` — эталонная картинка. Промпт (рабочий):
     `"<описание предмета>, as in the <комната> of the reference. Same stylized hand-painted 3D game art style, same materials and colors as the reference image. Single object only, centered, fully visible, isolated on a plain flat light-grey background, soft even studio lighting, 3/4 front view, no text, no shadows on background."`
  2. Затем картинку превращаем в 3D-модель (image-to-3D, см. раздел 4).
  3. Сжимаем `gltf-transform optimize` (webp 512, simplify 0.35, meshopt).

  Все готовые картинки-референсы лежат в `assets/refs/`, скрипт — `pipeline/genref.py`.

## 3. Технологии и устройство кода

**Стек (веб-прототип):**
- three.js 0.160 — с jsDelivr через importmap.
- Rapier 3D (`@dimforge/rapier3d-compat@0.12.0`) — физика.
- Один файл `game/index.html`, ES-модули, без сборщика.
- Тесты — headless Chromium + Playwright.

**Структура репозитория:**
```
game/            ← ВСЁ, из чего собирается опубликованный артефакт
  index.html     ← игра целиком (сцена, физика, ИИ героя, UI)
  *-glb.txt      ← 3D-модели в base64 (хостинг артефактов не отдаёт .glb)
  floor-atlas.jpg, bark2.jpg, roof2.jpg, ground2.jpg, leaf2.png ← текстуры из эталона
assets/models/   ← исходные .glb (сжатые, meshopt): дерево, 14 предметов, hero.glb (все анимации), zombie.glb
assets/refs/     ← 2D-референсы предметов/героя/зомби/дерева (из них делались 3D)
assets/textures-src/ ← исходники текстур (до тайлинга)
concept/         ← концепт-арты; 1-domik-razrez-3d.png — ЭТАЛОН
pipeline/        ← скрипты генерации ассетов (fal.py, genref.py, gen3d.py, rig*.py, pack.mjs, make_textures.py, build_txt.sh …)
tests/           ← Playwright-скрипты проверки (рендер, маршруты героя, тап-стрельба, ошибки страницы)
```

**Запуск локально:**
```
cd game && python3 -m http.server 8126
# открыть http://localhost:8126/index.html
```
Тесты (Chromium уже установлен в облачной среде; локально нужен `npm i playwright`):
```
node tests/page_errors.js       # грузится ли страница, ошибки JS
node tests/render_overview.js   # снимки день/сумерки/кухня
node tests/hero_routine.js      # герой: встал со стула → площадка (лестница) → спуск → кровать
```
- Пути вывода снимков внутри тестов указывают на временную папку — поправь под себя.
- В headless SwiftShader FPS низкий. `window.__TS = N` ускоряет игровое время, хуки отладки собраны в `window.__th` и `window.__dbg`.

**Публикация артефакта** (Claude Code, инструмент Artifact):
- Опубликуй `game/index.html` с `url: https://claude.ai/artifact/Ro32b6Sg7VRcXuuKDEq85d`.
- В `files` передай все `game/*.txt`, `*.jpg`, `*.png` — ключ равен имени файла.
- После замены `.glb` в `assets/models/` пересобери base64: `sh pipeline/build_txt.sh`.

**Как устроен `index.html`** (сверху вниз):
1. **Загрузка.** `tex()` / `glb()`. Модели декодируются из base64 через `GLTFLoader.parse`, для meshopt нужен `MeshoptDecoder`. Prop-модели складываются в `PROPS`.
2. **Свет и небо.**
   - `HemisphereLight` + `AmbientLight` (днём подсветка комнат) + солнце/луна `DirectionalLight` с тенями: 1024 на телефоне, 2048 на ПК.
   - Небо — шейдерная сфера. Цвета суток задаёт таблица `K` (часы → цвет неба/тумана/солнца, интенсивности, экспозиция); сумерки и ночь подогнаны под палитру эталона (`#335e7c`, `#2f6279`).
   - Лампы — `PointLight`, включаются от `lampOn` вечером. Их 6, не больше: больше было причиной тормозов.
3. **Дерево.** Модель масштабируется до 16 м. Треугольники делятся по цвету текстуры на кору и листья:
   - кора — отдельный меш с triplanar-текстурой `bark2.jpg` и **trimesh-коллайдер Rapier** (стрелы втыкаются, доски не проходят сквозь ствол);
   - листья исходной модели скрыты, вместо них ~2600 (на телефоне 1700) instanced-карточек `leaf2.png` — нарисованные гроздья дуба;
   - `SL` — горизонтальные срезы коры через каждые 10 см, функция `inTrunk()` проверяет, внутри ли ствола точка. По ней **доски пола и стен обрезаются вокруг ствола и веток**, а `cullLeaves()` убирает листья, влезающие в комнаты.
4. **Дом из досок.** Каждая доска — отдельное тело Rapier (fixed), которое можно сломать (`breakBoard`: становится dynamic, разлетаются щепки).
   - Рисуются двумя `InstancedMesh` (`boards` — светлые, `beams` — тёмные балки). UV каждой доски берёт одну из 8 строк атласа `floor-atlas.jpg`. Ширина 0.24 м, лёгкий случайный перекос — «неидеальные» доски.
   - Функции построения: `floorBoards`, `wallBack`, `wallSide`, `roof`, `post`, `brace`, `rail`, `ladder`, `ropeLadder`, `barricade`.
   - Планировка по эталону (высоты в метрах): нижняя площадка с дуплом-дверью LG 1.6, левая площадка LL 2.3, центральная полукруглая площадка LC 3.4, мастерская WS 3.6, кухня KT 5.0, спальня BD 7.4, смотровая площадка DK 9.0. Спальня стоит над кухней, её пол — это потолок кухни.
5. **Мебель.**
   - `prop(name, x, y, z, {h|w, ry, solid, seat})` ставит модель на пол. Твёрдые предметы попадают в `OBST` — прямоугольные «следы» на полу.
   - `pushOut()` не даёт герою войти в мебель, `navCheck()` (`__th.nav()`) проверяет, что маршруты не пересекают мебель.
   - Позы «сидит» и «лежит» подгоняются лучом к реальному сиденью и матрасу (блок `// fit poses to the furniture`).
6. **Герой (ИИ).**
   - Граф точек `N` + рёбра `E` (обычные, `ladder` — лестница, `ramp`), поиск пути BFS (`route`).
   - Задачи `TASKS` + `pickTask()` по времени суток; `startTask()` оборачивает переходы: встать со стула или с кровати перед новой задачей.
   - Ходьба `walkStep`: разгон и торможение, дуги, поворот на месте отдельным клипом.
   - Лестница `ladderStep`: подход → лазание (клип 437) → **вылез на пол** (клип 435 с root-motion: руки на край, подтягивается). Вниз — то же самое в обратную сторону. Параметры каждой лестницы — в `LAD`.
   - **Root-motion.** Клипы `57, 53, 435, 371, 271` не обрезаются по смещению таза. Смещения берутся из `HIPS[clip].s/.e`; `rmPlay()` проигрывает клип и в конце переносит корень персонажа на то смещение, которое прошёл таз.
7. **Анимации (ID клипов из библиотеки Meshy; все внутри `assets/models/hero.glb`):**

   | Группа | ID и назначение |
   |---|---|
   | Стойка | 0 Idle; 11, 12 — варианты стойки; 336 — дышит и оглядывается |
   | Ходьба | 30 Casual_Walk (основная); 9001 — старая базовая |
   | Повороты на месте | 576 влево, 586 вправо |
   | Лестница | 437 Slow_Ladder_Climb (цикл), 435 Ladder_Climb_Finish (вылезти наверх) |
   | Стул | 57 Stand_to_Sit, 33 Chair_Sit_Idle, 53 Sit_to_Stand |
   | Кровать | 371 Sit_Lie_Bed: сел на край и лёг (держим кадр 0.6 как сон), потом досматриваем до конца — сел, и встаёт клипом 53 |
   | Работа | 276 (готовит у печки), 128 (молоток), 342/343 — пьёт стоя или сидя |
   | Лук | 231 прицел, 224 выстрел |
   | Падение | 184 |

   - Зомби (`zombie.glb`): 113/111 — ходьба, 438 — лестница, 444 — по стене или свае, 198 — удары, 386 — крик, 183/502/178 — падение и реакция.
   - Сон 267 и 269 в пакете есть, но кровать сейчас использует 371.
8. **Камера.**
   - Перспектива, угол обзора 38°, чуть сверху и сбоку. Палец — поворот (yaw ±0.75, pitch), щипок или колесо — приближение (`zoom` 0.32…1).
   - При приближении камера следит за героем. По умолчанию в кадре весь домик, как на эталоне.
9. **Туман.** 6 вертикальных billboard-плоскостей с шейдером (fbm + domain warp), медленно клубится. Плюс обычный `scene.fog`.
10. **Производительность.**
    - На телефоне (`MOBILE`): pixelRatio ≤ 1.5, bloom выключен, тени 1024, листья без теней.
    - Адаптивно снижаем качество, если FPS < 40.
    - При `webglcontextlost` страница перезагружается.
    - `frame()` обёрнут в try/catch: раньше любая ошибка навсегда останавливала игру — это была причина «вечного зависания».
11. **Бой (сейчас выключен).**
    - Зомби ходят по маршрутам `ROUTES` (Калитка / Забор кухни / Забор мастерской), ломают доски `barricade`.
    - Тап по зомби → `fireAt()`: герой бежит на позицию из `GUARD` (выступ у двери, угол спальни, смотровая площадка), разворачивается, наклоняет корпус к цели и стреляет.
    - Траектория подбирается `solveShot()` с проверкой лучом Rapier. Стрела — физическое тело с CCD, при попадании зомби становится ragdoll из капсул на костях.
    - Включение: в `frameBody` вернуть `spawnLeft=3+dayNo*2` при наступлении ночи (сейчас `spawnLeft=0`).

## 4. Как генерируются ассеты

**Ключи:**
- В облачной среде Claude Code ключи fal / OpenAI / Railway **подставляет прокси**: в коде и запросах ключей нет и быть не должно. `pipeline/fal.py` шлёт запросы без заголовка авторизации.
- Вне этой среды нужен заголовок `Authorization: Key <FAL_KEY>`, ключ берёт владелец в fal.ai → Billing / Keys.
- Баланс fal пополняет владелец: было $25, потрачено около $6.

**fal.ai (очередь `https://queue.fal.run/<endpoint>`, опрос `status_url` → `response_url`):**

| Что | Endpoint | Настройки, которые сработали |
|---|---|---|
| 2D-референсы (предметы, герой, дерево без домика) | `fal-ai/nano-banana-pro/edit` | `image_urls:[эталон data-URI]`, `aspect_ratio 1:1` (дерево `3:4`), промпт-шаблон из раздела 2 |
| 3D герой/зомби/старое дерево | `fal-ai/meshy/v6/image-to-3d` | `enable_pbr`, `target_polycount` 24000 (персонажи) / 90–120k (дерево), `topology triangle`, для персонажей `pose_mode a-pose`, `enable_rigging`, `skeleton_template mixamo`, `rigging_height_meters` 1.6 / 1.75 |
| Анимации | `fal-ai/meshy/rigging` | `model_url` (= model_glb героя из `pipeline/hero-model.json`), `height_meters 1.6`, `skeleton_template mixamo`, `enable_animation true`, `animation_action_id <ID>`. Около 5 мин и примерно $0.3 за клип. Список ID: docs.meshy.ai/en/api/animation-library |
| Дешёвые 3D-пропсы (10 шт.) | `fal-ai/trellis` | `texture_size 1024, mesh_simplify 0.95, ss/slat_sampling_steps 20` — выходят темноватыми, в игре осветляем (`bright`) |
| Старое (не используется) | `esrgan`, `depth-anything`, elevenlabs и др. | — |

**Artlist (MCP-коннектор, на кредиты владельца; использовался, пока fal был без денег):**
- Новое дерево — Meshy v7 image-to-3D, 3 600 кредитов.
- Печь, верстак, подзорная труба, полки — Hyper3D Rodin v2.5 Fast, по 300 кредитов.
- Текстуры из эталона — Nano Banana Pro I2I 2K, по 160 кредитов.
- Гроздь листьев с прозрачным фоном — GPT Image 2.6 transparent, 110 кредитов.
- Промпт для текстур: `"From this treehouse painting, create a seamless tileable square texture of the <FLOOR planks / ROOF shingles / forest GROUND / tree BARK> exactly as painted here: … Flat orthographic view, even lighting, fills the whole frame, edges tile seamlessly."`
- Запрос «стены» трижды отбила модерация (ложное срабатывание), поэтому стены сейчас сделаны тем же атласом, только светлее (`tint`).

**Вручную и скриптами:**
- `pipeline/pack.mjs` склеивает анимации в один GLB по именам костей, затем resample, dedup, prune, webp 1024.
- `gltf-transform optimize --texture-compress webp --texture-size 512 --simplify-ratio 0.35 --compress meshopt` — пропсы; дерево сжималось с `--texture-size 2048 --simplify-ratio 0.6`.
- `pipeline/make_textures.py` — квадратные бесшовные тайлы и атлас досок: 8 строк по найденным швам.
- `pipeline/rootinfo.mjs` — смещения таза (root-motion) в клипах.
- Сырые анимации (около 13 МБ каждая) в репозиторий не положены: их можно пересоздать через `pipeline/rig2.py`.

## 7. Известные баги и недоделки (по приоритету)

1. **[Высокий] Подтвердить стабильность на iPhone.** Если всё ещё зависает: убрать тени с досок, сократить листья до примерно 800, туман до 3 слоёв, отказаться от `PointLight` в пользу запечённого света.
2. **[Высокий] Сходство с эталоном не «один в один».** Отличия:
   - листва темнее;
   - у комнат нет толстых «плит»-полов с тёмной окантовкой;
   - крыши тоньше, чем на эталоне;
   - ракурс шире;
   - нет каменных и травяных деталей у корней;
   - дупло-дверь меньше и прячется под мастерской;
   - на эталоне нет свай под площадками, у нас остались 2 (по ним лезут зомби).

   Делать сравнением рядом: тот же ракурс → снимок → правка.
3. **[Средний] Кровать.**
   - Поза сна — пауза клипа 371 на 60%: лежит с согнутыми коленями. Проверь в реальном времени, что она не проходит сквозь верхнюю полку.
   - Пробуждение: клип 371 до конца, затем 53 (вставание со стула) — переход заметно «прыгает».
   - Можно попробовать 271 Wake_Up.
4. **[Средний] Лестницы.**
   - На стыке «лазание → вылезание» небольшой рывок (≈0.28 м по высоте компенсируется сдвигом корня).
   - Спуск = обратное проигрывание 435, выглядит чуть неестественно.
   - Нужен отдельный клип «спуск с края» или подбор ID.
5. **[Средний] Стены** сделаны атласом пола (светлее), потому что отдельную текстуру стен не дала сгенерировать модерация. Попробовать другой промпт или модель.
6. **[Средний] Зомби при включении боя.**
   - Позиции стрельбы и маршруты подобраны под нынешнюю геометрию; при изменении дома проверять `tests/tap_shoot.js`.
   - Позицию «угол спальни» стоит проверить отдельно.
7. **[Низкий]**
   - `9001` (старая ходьба) и клипы 267/269 лежат в пакете, но не используются — удалить, чтобы уменьшить `hero.glb`.
   - Подсказка внизу экрана крупновата.
   - Предметы от trellis тёмные (компенсируется `bright`).
8. **[Низкий] Вес.** Всего около 15 МБ: персонаж 3.8 МБ + зомби 2.5 МБ + дерево 2.5 МБ, всё в base64 (+33%). Для App Store это норм, но в Swift использовать `.usdz` / `.glb` без base64.

## 8. План на будущее (по приоритету)

1. Стабильность на iPhone (пункт 1 раздела 7).
2. Довести стартовый кадр до эталона (пункт 2 раздела 7). Метод — систематическое сравнение рядом.
3. Довести переходы анимаций (кровать, лестница вниз), добавить мелкую жизнь: моргание, взгляд на камеру/объекты (look-at головы), звук шагов по доскам.
4. Включить бой обратно и сделать петлю: ночь → оборона → утро → ремонт досок → прогресс (новые доски, крепче забор).
5. Укрепление домика игроком: таскать и ставить доски физически, без «тапни светящийся квадрат» — это владелец отверг.
6. Другие убежища: поезд, домик на скале (концепты в `concept/2-…`, `3-…`).
7. **Перенос на Swift (SceneKit или RealityKit / Metal) и публикация в App Store.** Под это закладывать оптимизацию **без потери качества**:
   - правдоподобная физика, но крупными телами: доски да, отдельные листья и травинки нет;
   - листва и трава — несколько текстурных «шапок» и карточек, а не тысячи объектов;
   - свет частично запечённый;
   - в Swift: GLB → USDZ, физика — SceneKit physics или порт Rapier.

## 9. Решения, которые уже приняты, и что не сработало

**Принято:**
- Настоящий 3D-мир с физикой (Rapier), а не «ожившая картинка».
- Вид в разрезе (cutaway), камера чуть сверху; камеру можно крутить.
- Стиль и текстуры берутся из эталонной картинки.
- Герой и зомби — модели Meshy с mixamo-скелетом; анимации — библиотека Meshy через fal `meshy/rigging`.
- Стрельба — тап по зомби, а не натягивание пальцем.
- Зомби пока выключены.
- После каждой доработки — сразу обновлять артефакт (просьба владельца).
- Ключи в коде не храним.

**Пробовали, не сработало (не повторять):**
- Игра «заводные игрушки» на cannon-es: физика и эффекты «полная хрень» по словам владельца.
- 2D-«ожившая картинка» (`th2`) — отвергнута.
- Процедурный домик из коробок и примитивов, прямоугольные доски без текстуры — отвергнуты.
- Механика «тапни светящийся квадрат, чтобы поставить доску» — отвергнута.
- Зомби, которые телепортируются наверх или кувыркаются от тапа, — отвергнуты.
- Длинный плоский фасад дома перед деревом и камера в лоб — выглядело как 2D. Сейчас комнаты стоят вокруг ствола на разной высоте.
- Сваи и столбы под всем домом — на эталоне их нет.
- Листья исходной модели Meshy — плоские «осколки»; заменены карточками-гроздьями.
- Туман из 10 слоёв с 5 октавами шума, 12 `PointLight`, тени 2048 на телефоне — тормоза и зависания.
- `fal-ai/meshy/animation` и `tripo3d` на fal недоступны или без цены — использовать `meshy/rigging` с `animation_action_id`.
- Хостинг артефактов не отдаёт `.glb` — поэтому base64 `.txt`.
- GTAO делал чёрные квадраты на спрайтах (в прошлых демо); bloom с низким порогом засвечивал сцену (порог около 1.1 и выше).
